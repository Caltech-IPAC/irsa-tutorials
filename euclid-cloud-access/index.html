Euclid DR1: Cloud Access

Learning Goals¶

By the end of this tutorial, you will:

  • Learn where Euclid DR1 data are stored in the cloud.

  • Retrieve an image cutout from the cloud.

  • Retrieve a spectrum from the cloud.

1. Introduction¶

Euclid launched in July 2023 as a European Space Agency (ESA) mission with involvement by NASA. The primary science goals of Euclid are to better understand the composition and evolution of the dark Universe. The Euclid mission is providing space-based imaging and spectroscopy as well as supporting ground-based imaging to achieve these primary goals. These data will be archived by multiple global repositories, including IRSA, where they will support transformational work in many areas of astrophysics.

Euclid Data Release 1 (DR1) comprises about 1900 sq deg of imaging, spectroscopy, and catalogs from the Euclid Wide Survey (EWS) and from the Euclid Deep Survey (EDS), which covers about 53 sq deg in the three Euclid Deep Fields (North, South, and Fornax). It follows Quick Release 1 (Q1); all of the DR1 data, including the areas observed in Q1, have been reprocessed with updated pipelines and calibrations.

IRSA maintains copies of the Euclid DR1 data products on the cloud via Amazon Web Services (AWS). This notebook provides an introduction to accessing Euclid DR1 data from the cloud. If you have questions, please contact the IRSA helpdesk.

2. Imports¶

  • s3fs for browsing S3 buckets

  • astropy for handling coordinates, units, FITS I/O, tables, images, etc.

  • astroquery>=0.4.11 for querying Euclid data products from IRSA

  • matplotlib for visualization

  • json for decoding JSON strings

Note

Please make sure you have astroquery version v0.4.11 or newer installed.

4. Do a spatial search for MER mosaics¶

Pick a target and search radius. We give the target’s coordinates directly; you could instead look them up by name with SkyCoord.from_name(target_name).

target_name = 'WISEA J181204.48+681354.0'
coord = SkyCoord(ra=273.018690, dec=68.231680, unit='deg')
search_radius = 10 * u.arcsec

As per “Data Products Overview” in user guide, DR1 MER mosaics come in two kinds of tiles, which IRSA serves as two separate collections:

  • Wide tiles (euclid_dr1_wide_DpdMerBksMosaic): tile IDs start with 102, about 32 x 32 arcmin.

  • Deep tiles (euclid_dr1_deep_DpdMerBksMosaic): tile IDs start with 101, about 17 x 17 arcmin, covering the Euclid Deep Fields and auxiliary fields.

Our target lies in the Euclid Deep Field North, so we use the deep collection:

img_collection = 'euclid_dr1_deep_DpdMerBksMosaic'

Now query this collection for our target’s coordinates and search radius:

img_tbl = Irsa.query_sia(pos=(coord, search_radius), collection=img_collection)

euclid_sci_img_tbl = img_tbl[[row['facility_name']=='Euclid'

We can see there’s a cloud_access column that gives us the location info of the image files we are interested in. So let’s extract the S3 bucket file path from it:

def get_s3_fpath(cloud_access):
    cloud_info = json.loads(cloud_access) # converts str to dict
    bucket_name = cloud_info['aws']['bucket_name']
    key = cloud_info['aws']['key']

    return f'{bucket_name}/{key}'

5. Efficiently retrieve mosaic cutouts¶

These image files are very big (~1.4GB), so we use astropy’s lazy-loading capability of FITS for better performance. (See Obtaining subsets from cloud-hosted FITS files.)

cutout_size = 1 * u.arcmin
cutouts = []
filters = []

for row in euclid_sci_img_tbl:
    s3_fpath = get_s3_fpath(row['cloud_access'])
    filter_name = get_filter_name(row['instrument_name'], row['energy_bandpassname'])

    with fits.open(f's3://{s3_fpath}', fsspec_kwargs={"anon": True}) as hdul:
        print(f'Retrieving cutout for {filter_name} ...')
        cutout = Cutout2D(hdul[0].section,
                          position=coord,
                          size=cutout_size,
                          wcs=WCS(hdul[0].header))
        cutouts.append(cutout)
        filters.append(filter_name)

First, list the Euclid catalogs provided by IRSA. We use include_metadata_tables=True so that the list also includes metadata tables, such as the one that associates objects with their spectra.

catalogs = Irsa.list_catalogs(full=True, filter='euclid', include_metadata_tables=True)

From this table, we can extract the MER catalog name. 8. Find the spectrum of an object in the MER catalog¶

Using the object ID(s) we extracted above, we can narrow down the spectral file association catalog to identify spectra file path(s). So we do the following TAP search:

adql_query = f"SELECT * FROM {euclid_spec_association_catalog} \
    WHERE objectid = {object_id}"

spec_association_tbl = Irsa.query_tap(adql_query).to_table()
spec_association_tbl
Loading...
Warning

If you picked a target other than what this notebook uses, it’s possible that there is no spectrum associated for your target’s object ID. In that case, spec_association_tbl will contain 0 rows.

In above table, we can see that the 'path' column gives us the location of the combined spectra file that contains our object, and the 'hdu' column gives us the extension number for our object. Together they can be used to call an IRSA service to get the spectrum of our object as a SpectrumDM VOTable, at https://irsacloud.ipac.caltech.edu/api/spectrumdm/convert/{path}?dataset_id=euclid_combspec_dr1&hdu={hdu}. Here we instead retrieve the spectrum from the cloud: removing the leading euclid/ from the path gives us the S3 bucket key of the spectra file. This is a very big FITS spectra file with multiple extensions where each extension contains spectrum of one object. So let’s extract both the key and the extension number.

spec_fpath_key = spec_association_tbl['path'][0].removeprefix('euclid/')
spec_fpath_key
'dr1/SIR_COMBINED_SPECTRA/101839130/EUC_SIR_W-COMBSPEC_101839130_20250908T142948.154355Z.fits'
object_hdu_idx = int(spec_association_tbl['hdu'][0])
object_hdu_idx
6563

Again, we use astropy’s lazy-loading capability of FITS to only retrieve the spectrum table of our object from the S3 bucket.

with fits.open(f's3://{BUCKET_NAME}/{spec_fpath_key}', fsspec_kwargs={'anon': True}) as hdul:
    spec_hdu = hdul[object_hdu_idx]
    spec_tbl = Table.read(spec_hdu, unit_parse_strict="silent")
    spec_header = spec_hdu.header
spec_tbl
Loading...

The MASK column flags flux bins that should not be used; bins with an odd MASK value or a value of 64 or more are flagged. These include the low-flux bins at both ends of the wavelength range, so we set the y-axis range from the unflagged bins to show the spectrum in more detail.

good = (spec_tbl['MASK'] % 2 == 0) & (spec_tbl['MASK'] < 64)
good_signal = spec_tbl['SIGNAL'][good]
margin = 0.05 * (good_signal.max() - good_signal.min())

# In DR1, the flux scale factor (the FSCALE header keyword) is already included in the unit of the SIGNAL column,
# so we plot the signal as is and label the axis with that unit.
plt.plot(spec_tbl['WAVELENGTH'], spec_tbl['SIGNAL'])
plt.ylim(good_signal.min() - margin, good_signal.max() + margin)
plt.xlabel(spec_tbl['WAVELENGTH'].unit.to_string('latex_inline'))
plt.ylabel(spec_tbl['SIGNAL'].unit.to_string('latex_inline'))

plt.title(f'Spectrum of Target: {target_name}\n(Euclid Object ID: {object_id})');
