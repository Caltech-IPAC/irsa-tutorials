Euclid DR1 HATS Catalogs: Introduction

This tutorial is an introduction to the content and format of the Euclid DR1 HATS Catalogs, a set of catalogs that IRSA created from the Euclid Data Release 1 (DR1) catalogs and spectra.

Learning Goals¶

In this tutorial, we will:

  • Learn which Euclid DR1 catalogs are available in HATS format and how they are named and organized.

  • Load the schema (column information) of a catalog and find columns of interest.

  • Perform basic queries using the Python libraries PyArrow and LSDB.

  • Load and plot a combined 1D spectrum.

1. Introduction¶

Euclid DR1 contains data from the first year of survey operations, covering approximately 1,900 square degrees of the Euclid Wide Survey, as well as observations of the Euclid Deep Fields, calibration fields, and Performance Verification data. The DR1 catalogs were derived from Euclid photometry and spectroscopy, taken by the Visible Camera (VIS) and the Near-Infrared Spectrometer and Photometer (NISP), and from photometry taken by other ground-based instruments. For descriptions of the releases, surveys, data products, and access methods, see the Euclid Archive User Guide.

Euclid DR1 catalog data are separated into about 25 merged-mosaic, photo-z, and spectroscopy catalogs, which are further split by survey or processing mode (e.g., deep survey), for a total of 93 individual catalogs. IRSA is creating various HATS (Hierarchical Adaptive Tiling Scheme) products and releasing them as they become available.

Currently, IRSA provides 56 HATS catalogs corresponding to individual Euclid DR1 catalogs, plus 1 HATS catalog with DR1 spectra. For the Q1 release, IRSA joined most of the individual catalogs together into a single Merged Objects HATS product (see Euclid Q1 Merged Objects HATS Catalog: Introduction). We intend to provide similar products for Euclid DR1 in the near future.

The catalogs are served from an AWS S3 cloud storage bucket. Access is free and no credentials are required.

1.1 Duplicate object IDs¶

Most DR1 catalogs have more than one row with the same object_id, meaning object_id alone usually does not identify a unique row. There are a few reasons for this, including:

  1. Euclid object IDs are constructed from RA and dec coordinates that are truncated such that objects that are very close together on the sky ended up with the same object ID.

  2. Most spectroscopy catalogs have, for example, several redshift solutions or several spectral lines per object, each stored in its own row.

  3. Euclid DR1 provides red and blue grism spectra, with each spectrum in its own row, and many objects have both.

Things to expect when working with these catalogs:

  • Looking up an object by its object_id can return more than one row. This includes lookups that use a catalog’s index table (for example, LSDB’s id_search), which return every row with that object_id.

  • It’s often not clear how to join two catalogs when either or both contain duplicated object_ids. So the user must choose if they want to drop the duplicates, choose one of the possible permutations, accept all possible permutations, or make some other choice.

  • When an object_id value appears more than once in a given catalog, those rows might belong to different Euclid objects that are close enough on the sky to end up with the same object ID, or they might belong to different measurements for the same Euclid object.

    • Non-spectroscopy catalogs generally keep data for one Euclid object on one row, so duplicates there are likely to be different Euclid objects.

    • However, most spectroscopy catalogs separate one Euclid object into multiple rows (one row per redshift solution, for example), and may also contain different Euclid objects that happen to have the same object_id.

3. Available Catalogs¶

The HATS catalogs currently available are from the Deep Survey, Deep, Wide Survey, and Wide tables, plus the 1D combined spectra. The original data products were produced by four Euclid processing functions: MER (multi-wavelength mosaics on common spatial and pixel scales), PHZ (photometric redshifts), SPE (spectroscopy), and SIR (NISP spectra). For details, see Data Products in the Euclid Archive User Guide.

The suffix in each catalog name is the suffix of the original Euclid table, and the suffixes differ between processing functions:

  • MER: _deep_survey and _wide_survey

  • PHZ: _deep_survey and _wide

  • SPE: _deep, _wide_survey, and _wide

For what each survey and suffix means, see the Euclid Archive User Guide.

The tables below list each catalog and its number of rows. “Not yet” means the table is in Euclid DR1 but IRSA has not yet released a HATS catalog for it. “Not in DR1” means Euclid DR1 does not contain that table.

3.1 SIR combined 1D spectra¶

Original schema: SIR combined spectra data product

TableRows
sir_combined_spectra309,078,775

sir_combined_spectra contains the combined 1D spectra, with one row per spectrum. An object can have more than one spectrum, so it can appear in more than one row. For example, an object can have both a red grism spectrum and a blue grism spectrum, which are identified by the column lrange (values RGS and BGS). An object can also have more than one spectrum with the same lrange, so object_id and lrange together do not uniquely identify a row. The spectrum itself is stored in a single nested column, spectrum.

3.5 Catalog paths¶

Each catalog is stored in its own HATS collection. A collection contains the catalog itself, plus ancillary data that some libraries (such as LSDB) use to make queries faster: a margin cache and an index table on object_id. The collection for a catalog is at hats/reformatted_catalogs/<catalog>/ and the catalog inside it is named euclid_dr1_reformatted_catalogs_<catalog>-hats.

The collections can be browsed here.

In the rest of this tutorial we use the MER catalog for the Deep Survey, mer_catalogue_deep_survey.

# AWS S3 paths.
s3_bucket = "nasa-irsa-euclid-dr1"
collection_prefix = "contributed/dr1/hats/reformatted_catalogs/mer_catalogue_deep_survey"
catalog_name = "euclid_dr1_reformatted_catalogs_mer_catalogue_deep_survey-hats"

collection_path = f"{s3_bucket}/{collection_prefix}"
dataset_path = f"{collection_path}/{catalog_name}/dataset"
schema_path = f"{dataset_path}/_common_metadata"

# S3 pointer. Use `anonymous=True` to access without credentials.
s3 = pyarrow.fs.S3FileSystem(anonymous=True)

4. Column Names and Added Columns¶

First we’ll load the Parquet schema (column information) of the catalog. The Parquet schema is accessible from a few locations, all of which include the column names and types. Here, we load it from the _common_metadata file because it also includes the column units and descriptions.

# Load the Parquet schema.
schema = pyarrow.parquet.read_schema(schema_path, filesystem=s3)

print(f"{len(schema)} columns in the {catalog_name} catalog")
483 columns in the euclid_dr1_reformatted_catalogs_mer_catalogue_deep_survey-hats catalog

The original tables’ column names are mostly in all caps. In the HATS catalogs and the catalogs available through IRSA’s TAP service, all column names have been lower-cased. In addition, the characters -, ., (, and ) have been replaced with an underscore. An example that includes both transformations is: E(B-V) -> e_b_v_. Unlike the Q1 Merged Objects catalog, the table name is not prepended to the column names.

In the MER catalogs, three columns were renamed to match other IRSA services:

  • ra : ‘RIGHT_ASCENSION’

  • dec : ‘DECLINATION’

  • tileid : ‘TILE_INDEX’, the ID of the Euclid tile the object was detected in.

Two columns were added to every catalog. They contain the object’s coordinates, calculated from its object_id following the MER catalog description. They were used to partition the catalogs spatially, including the PHZ and SPE catalogs that don’t have RA and Dec columns of their own.

  • ra_from_object_id : RA coordinate (degrees) calculated from object_id.

  • dec_from_object_id : Dec coordinate (degrees) calculated from object_id.

HEALPix columns:

These HEALPix indexes correspond to the ra_from_object_id and dec_from_object_id coordinates. They are useful for spatial queries.

  • _healpix_9 : HEALPix order 9 pixel index. Order 9 pixels have a resolution (square root of area) of ~400 arcseconds or ~0.1 degrees.

  • _healpix_19 : HEALPix order 19 pixel index. Order 19 pixels have a resolution of ~0.4 arcseconds.

  • _healpix_29 : HEALPix order 29 pixel index. Order 29 pixels have a resolution of ~4e-4 arcseconds.

The HEALPix columns and the added coordinate columns appear first:

schema.names[:5]
['_healpix_29', '_healpix_19', '_healpix_9', 'ra_from_object_id', 'dec_from_object_id']

HATS columns:

These are the HATS partitioning columns. They appear in the Parquet file names but are not included inside the files. However, PyArrow automatically makes them available as regular columns when the dataset is loaded as demonstrated in this tutorial.

  • Norder : (hats column) HEALPix order at which the data is partitioned.

  • Npix : (hats column) HEALPix pixel index at order Norder.

  • Dir : (hats column) Integer equal to 10_000 * floor[Npix / 10_000].

The HATS columns appear at the end:

schema.names[-3:]
['Norder', 'Dir', 'Npix']

5. Basic Query with PyArrow¶

To demonstrate a basic query, we’ll search for bright, point-like objects detected in the VIS mosaic. The columns used in this query are described in more detail in Euclid Q1 Merged Objects HATS Catalog: Magnitudes. PyArrow dataset filters are described at Filtering by Expressions, and the list of available functions is at Compute Functions.

dataset = pyarrow.dataset.dataset(dataset_path, partitioning="hive", filesystem=s3, schema=schema)

columns = ["object_id", "ra", "dec", "flux_vis_psf", "point_like_prob"]
bright_point_sources = (
    (pc.field("vis_det") == 1)  # detected in the VIS mosaic
    & (pc.field("spurious_flag") == 0)  # not flagged as spurious
    & (pc.field("point_like_prob") > 0.99)  # point-like
    & (pc.field("flux_vis_psf") > 1_000)  # brighter than 1 mJy in VIS
)

bright_objects = dataset.to_table(columns=columns, filter=bright_point_sources).to_pandas()

6. Cone Search with LSDB¶

LSDB is a Python library built for HATS catalogs. It is especially good for spatial searches and cross matches. We can pass it the collection path and it will find the catalog inside it and use the ancillary data (such as the margin cache) when needed. We prefix the path with s3:// to indicate that it is an S3 path.

LSDB loads data lazily. Here we open the catalog with only the columns we need and set up a cone search with a 2 arcminute radius around the planetary nebula NGC 6543, which is in the Euclid Deep Field North.

mer_deep = lsdb.open_catalog(
    f"s3://{collection_path}",
    columns=["object_id", "ra", "dec", "flux_vis_psf", "point_like_prob"],
)

ngc6543_ra, ngc6543_dec = 269.6394799, 66.6329765  # degrees
ngc6543_cone = mer_deep.cone_search(ra=ngc6543_ra, dec=ngc6543_dec, radius_arcsec=120)
ngc6543_cone

7. Load and Plot a Spectrum¶

sir_combined_spectra contains the combined 1D NISP spectra (Section 3.1). Here we find the spectra of EX Dra, an eclipsing cataclysmic variable in the Euclid Deep Field North, with a cone search of 1 arcsecond around its position.

spectra_collection_path = f"{s3_bucket}/contributed/dr1/hats/reformatted_catalogs/sir_combined_spectra"
spectra_catalog = lsdb.open_catalog(
    f"s3://{spectra_collection_path}",
    columns=["object_id", "tileid", "lrange", "n_dith", "spectrum"],
)

exdra = SkyCoord(ra=271.05936903 * u.deg, dec=67.90340938 * u.deg)
exdra_spectra = spectra_catalog.cone_search(ra=exdra.ra.deg, dec=exdra.dec.deg, radius_arcsec=1).compute()
exdra_spectra[["object_id", "tileid", "lrange", "n_dith"]]

Each row is one spectrum, so the same object_id can appear more than once (see Section 1.1), for example once for the red grism (RGS) and once for the blue grism (BGS). The cone search also returns several object_ids within a fraction of an arcsecond of each other, from two Euclid tiles. The column n_dith is the number of exposures (dithers) combined into each spectrum, so we keep the spectra of the object observed with the most dithers, choosing the one nearest EX Dra’s position if more than one has the same number.

spectra_coords = SkyCoord(
    ra=exdra_spectra["ra_from_object_id"].to_numpy() * u.deg, dec=exdra_spectra["dec_from_object_id"].to_numpy() * u.deg
)
offset_arcsec = exdra.separation(spectra_coords).arcsec
best = exdra_spectra.assign(offset_arcsec=offset_arcsec).sort_values(["n_dith", "offset_arcsec"], ascending=[False, True])
exdra_object = exdra_spectra[exdra_spectra["object_id"] == best["object_id"].iloc[0]]
exdra_object[["object_id", "tileid", "lrange", "n_dith"]]

LSDB returns query results as a nested-pandas NestedFrame, and spectrum is a nested column. Nested-pandas provides methods for querying and operating on nested columns without unpacking them; see its documentation for details. In each row, spectrum holds a small table with one row per wavelength bin and these columns:

  • wavelength : wavelength (Angstrom)

  • signal : flux, in units of 10-16 erg s−1^{-1}−1 cm−2^{-2}−2 Å−1^{-1}−1 (see below)

  • var : variance of the flux, in units of 10-32 erg2^22 s−2^{-2}−2 cm−4^{-4}−4 Å−2^{-2}−2

  • mask : pixel mask

  • quality : pixel quality flag

  • ndith : number of spectra used in the combination

# The spectrum in the first row, as a pandas DataFrame.
exdra_object.iloc[0]["spectrum"]

Following the Euclid Q1 1D spectra tutorial, we don’t use wavelength bins with an odd mask value or a mask value of 64 or more. Those bins are left as gaps in the plot.

The signal values are stored scaled, as in the original FITS files, where the scale factor is the FSCALE header keyword (10-16 for every spectrum). The unit recorded in this catalog’s metadata (erg/s/cm2/Angstrom) is missing that factor, so we multiply by it before plotting.

# signal is stored in units of 1e-16 erg/s/cm2/Angstrom (FITS keyword FSCALE). The catalog's unit metadata omits this factor.
FSCALE = 1e-16

fig, ax = plt.subplots(figsize=(10, 4))
for _, row in exdra_object.iterrows():
    spectrum = row["spectrum"]
    bad = (spectrum["mask"] % 2 == 1) | (spectrum["mask"] >= 64)
    flux = spectrum["signal"] * FSCALE
    ax.plot(spectrum["wavelength"] / 1e4, flux.where(~bad), label=f"{row['lrange']} (n_dith {row['n_dith']})")

ax.set_xlabel("Wavelength (micron)")
ax.set_ylabel("Flux (erg s$^{-1}$ cm$^{-2}$ Å$^{-1}$)")
ax.set_title("EX Dra")
ax.legend()
plt.show()
